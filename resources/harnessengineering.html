The short version

The model is an engine.
The harness is the vehicle.

The harness turns a model call into a dependable workflow. It decides what context the model sees, which actions it may take, where state lives, when to retry or stop, and how a person can inspect the result.

Your capstone

Build a tiny harness.
Make every part visible.

Keep the first version deliberately small. The goal is not autonomy; it is to understand the control surface well enough to explain every decision.

Suggested task

Give an agent a folder of notes and ask it to produce a sourced, one-page research brief.

  1. 01

    Define done

    Write the task, allowed sources, output format, and five acceptance criteria before the first model call.

  2. 02

    Limit the tools

    Start with one or two clearly described tools. Validate their inputs and return useful errors.

  3. 03

    Persist state

    Save a small progress file containing completed work, remaining work, decisions, and evidence.

  4. 04

    Run the loop

    Make plan → act → observe explicit. Log each step so you can explain why the next action happened.

  5. 05

    Design failure

    Add a time limit, step budget, retry rule, and a useful stop condition before something goes wrong.

  6. 06

    Write five evals

    Test success, missing data, conflicting evidence, a broken tool, and an instruction the agent must refuse.

  7. 07

    Keep a human gate

    Require approval before publishing, messaging, spending, deleting, or changing an external system.
