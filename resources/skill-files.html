How to build your own Claude skill file

A skill file teaches Claude how you want one job done, like 3D animation, essays or apps. Here is how the file is laid out, five tips that make Claude actually use it, and a full example you can copy.

The structure 1. Description 2. Keep it thin 3. Log failures 4. Scripts 5. Keep a score Full example

The structure

A skill is a folder with one main file.

The main file is always called SKILL.md. Everything else is optional, and Claude opens it only when the main file points to it.

essay-editor/
├── SKILL.md          # the skill itself
├── scripts/
│   └── check.py      # code for the exact steps
└── references/
    └── examples.md   # read only when needed
  • 1. DescriptionAt the top of SKILL.md. It tells Claude when to use the skill.
  • 2. InstructionsOnly what Claude would get wrong on its own. Short.
  • 3. MistakesA running list of every failure, so it is not repeated.
  • 4. ScriptsCode for anything that must come out the same every time.
  • 5. ScoreA yes/no checklist of what good looks like.
Tip 1

Write a description that is a bit pushy.

Claude reads every skill's description at the start and decides from that alone whether to open the skill. It tends to skip them, so say exactly when to use it and list the words people actually type.

Anthropic's Claude Code team puts it this way: the description is not a summary, it is a description of when to trigger the skill.

Tip 2

Keep it extremely thin.

Skip what Claude already knows. Write down the mistakes it keeps making instead. Every line should change what Claude does.

Tip 3

Every failure becomes a stepping stone.

A skill file is never finished. Each time Claude gets something wrong, note it down in the file and tell Claude not to do it again. The list grows, and the skill gets better every week.

Anthropic calls this gotchas list the highest-signal part of any skill.

Tip 4

Put script files in your skill.

If code can do it, don't let the AI guess. A script gives the same answer every time, so counting, checking and formatting never get hallucinated. Point to it from SKILL.md.

Tip 5

Keep a score.

Write a yes-or-no checklist of what good looks like. Then change one thing at a time in the skill, run it again, and keep the version that scores better. It is your own benchmark.

Full example

The whole skill file, all five parts.

Save it as ~/.claude/skills/essay-editor/SKILL.md for Claude Code, or upload the zipped folder in the Claude app's Skills settings. Then swap in your own job, rules and mistakes.

---
name: essay-editor
description: Edit any essay, blog post or long caption. ALWAYS use this when the user says "edit", "rewrite", "make it sound human" or pastes more than 3 paragraphs.
---

# Essay editor

## Instructions
- Keep my words. Cut, don't rewrite.
- No em dashes. Use commas.
- Never open with "In today's world".
- Max 2 sentences per paragraph.

## Mistakes
- Added a summary nobody asked for.
- Changed my quotes. Never edit a quote.
- Turned my list into a table.
- Said "delve". Banned word.
- Cut the joke in the intro. Keep jokes.

## Before you reply
Run `python scripts/check.py essay.md` and fix everything it flags.
For examples of my style, read references/examples.md.

## Score (yes / no)
- Still sounds like me?
- Under 800 words?
- No banned words?
- First line makes you read on?
- Every quote unchanged?

Keep in mind

It takes time, and it is worth it.

  • Start small.One job per skill. A skill that tries to do everything confuses Claude about when to use it.
  • Don't write every step.Give the goal and the rules. Claude handles the rest better than a long script of steps.
  • Long details go in other files.Keep SKILL.md short and point to references/ for examples, so Claude reads them only when needed.
  • Steal good examples.Anthropic's own skills are open source on GitHub. Read a few before you write yours.
